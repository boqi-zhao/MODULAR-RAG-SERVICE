5. 后续接入 FastAPI 批次提交、状态/产物查询及进度推送，按至少 10 用户需求设计，具体接口届时确定。

实现时遵守每次代码写入不超过 100 行、每 10–15 行代码补充说明性注释的约定。
先解释小步骤的逻辑，用户指示开始后再实现；完成后展示结果与代码，再决定下一步。不采用 TDD，按实际风险验证并执行 Ruff 检查。
完整 PDF 流程实现后执行 10 用户端到端脚本验收，分别设置内部文档并发 1/3，不以接口返回代替完成验收。

### 7.1 关键验收场景

| 场景 | 应满足的结果 |
| --- | --- |
| 文档路径变更，但仍指定同一文档且字节相同 | 文档版本保持一致；身份不随路径变化 |
| 同一字节接入为两份逻辑文档 | 文档身份分开，可共享原始字节存储 |
| 相同配置强制重跑 chunk | 新块集合和产物，历史结果保留；新旧块以证据范围对照 |
| caption 重跑两次 | 两次均读取固定基础表示，不重复追加历史 caption |
| Dense/Sparse ID 一致，实际输入文本版本不同 | 拒绝组合为 ready 索引 |
| 分块数从 100 减少至 80 | 新索引恰含新清单的 80 块，旧 20 块不会残留 |
| BM25 同一数据重复构建 | 每份快照每块只有一份记录，完整语料统计保持一致 |
| 目录发布后、状态库登记前崩溃 | 恢复校验并登记完整产物，不重复覆盖 |
| 旧 worker 在租约过期后返回结果 | fencing 校验拒绝提交，不覆盖恢复执行结果 |
| 上游文件损坏 | 拒绝复用和下游读取，错误可定位到文件及摘要 |

## 8. 待评审事项

- PostgreSQL 驱动、迁移、数据库任务分发与连接预算；Redis/Kafka 仍按需求另行评审。
- 用户身份、典型 PDF/批次规模、进度延迟与完成时限，参见 [并发验收边界](../04-concurrency.md)。
- 文档接入时的身份管理界面，以及来源 URI/路径变更的登记方式。
- refine 是否确实只改变表示；若需删块、合并或拆块，应重新划分阶段并生成块集合。
- 模型调用失败的重试策略、记录粒度，以及无法固定远程模型版本时的复用政策。
- 图片版本存储方式、Dense 模型、分词器和索引后端仍待评审；首批 PyMuPDF 选型、扫描规则与坐标约定已确认，依赖版本在重写时锁定，后续格式不在当前范围。
- 数据保留、导出、垃圾回收、磁盘配额与外部索引孤立空间的回收策略。
- 在线索引发布、跨解析器证据映射和评测指标细节由对应阶段继续设计。
