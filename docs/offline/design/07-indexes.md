# 语料与索引快照

状态：设计或用例建议；具体批准范围见对应评审入口。

## 6. 语料与索引快照

语料快照保存有序成员清单：文档版本、块集合、选定块表示、参与检索的 chunk_id 与输入摘要。
同一文档在一个快照中默认只选一个版本及块集合；确需多版本共存时需显式另定策略。
Corpus 的成员数与检索块数分别记录，空语料默认拒绝建索引，避免 N/平均长度出现无定义计算。
新语料先完整校验，之后编码；删除文档或改变分块都生成新的完整成员清单。

每次新的索引写入分配独立命名空间与 BM25 存储位置，不覆写其他快照。
恢复时新组合可以显式复用已成功的不可变分支，引用其原命名空间；失败分支分配新空间。
vector_write 与 bm25_build 可独立执行，完成后由 Runner 校验组合并生成索引快照 manifest。
组合校验要求两侧语料 ID、chunk_id 集合、块表示摘要一致，向量维度和稀疏参数符合契约。
索引 manifest 固定两侧 artifact_id、语料 ID、命名空间、后端版本及校验摘要。
初期组合要求 Dense 和 Sparse 两侧齐备；单侧检索快照作为后续能力另行设计。
索引快照仅在双方成功且校验通过后由 building 进入 ready，失败时进入 failed。
ready manifest 保持不可变；后续完整性问题可在状态库标记 unavailable，不改写历史来源。
离线索引 ready 只表示可供读取，不隐式发布到在线服务。

### 6.1 重复写入与旧块处理

- 向量后端使用原始 chunk_id 作为记录 ID，禁止按路径、文本或块位置重新推导另一套 ID。
- 新分块方案写入新命名空间，因此旧块不可能混入新快照；历史命名空间按保留策略保存。
- BM25 初期从固定完整语料重新构建，不增量拼接 postings，也不按文档 ID 前缀清理。
- BM25 的 N 是实际参与检索的块数，DF 是包含词项的块数，平均长度按同一清单的块计算。
- sparse_encode 保存逐块词项统计；bm25_build 才计算完整语料统计及具体打分参数。
- 构建失败可能留下部分外部写入，标记不可查询；恢复使用新候选索引 ID，不继续污染旧空间。
- 同一次 vector_write 内部批次重试沿用候选空间与 chunk_id；最终校验完整 ID 清单、数量和摘要。
- 两个分支只成功一个时保留诊断与成功产物，组合快照不得 ready；恢复显式引用保留的成功分支。
