# 执行状态与重跑

状态：设计或用例建议；具体批准范围见对应评审入口。

## 5. 执行与重跑语义

任务先形成不可变执行计划：固定根输入、配置、可选阶段、已有上游引用及依赖图。
计划内新阶段的输入引用在其上游成功后一次性记录；之后重试不得解析为最新版本。
同一计划中后续阶段明确使用本计划新产物；未受影响的依赖继续绑定原有快照。
阶段重跑方式与是否允许复用是两个独立选项，避免把“恢复”和“强制”混为一种模式。

| 操作 | 选择范围 | 输入及结果 |
| --- | --- | --- |
| 单阶段执行 | 仅指定阶段 | 必须提供完整上游引用；不自动补跑依赖或更新下游 |
| 下游重跑 | 指定节点及计划中的传递后继 | 新建计划；受影响节点读新结果，其余依赖仍固定旧快照 |
| 失败恢复 | 原计划未完成节点 | 已成功产物经校验后保留；失败/中断节点新建尝试 |
| 强制执行 | 上述范围中的指定节点 | 绕过复用、生成新产物；是否重跑后继由范围决定 |

失败恢复固定原配置和输入；改变参数或实现版本属于新计划，不能冒充原任务恢复。
初期恢复以整个阶段为单位，不承诺断点批次续跑；成功上游不会因为重试而被覆盖。
单阶段重跑 dense 不自动重跑 sparse；已有组合索引仍引用旧 dense，新组合需重新构建。
上游内容变化后不改写历史下游，只在新计划中构建新版本；旧实验仍保持可读。
索引语料包含其他文档时，下游计划保留其他成员，仅替换选中文档对应的块表示。
同一任务的独立分支可并行；某分支失败后阻断依赖它的后继，另一分支成功产物保留。

### 5.1 状态与可观测性

执行尝试状态为 queued → running → succeeded / failed / interrupted。
校验失败属于 failed；interrupted 表示执行失去租约或进程中断，恢复会创建新尝试。
复用是计划节点的 reused 结果，记录复用的 artifact_id，不伪造一个实际执行尝试。
任务状态聚合为 queued、running、succeeded、failed；有失败且其他分支尚在运行时仍为 running。
任务因失败结束后恢复可回到 queued/running，但历史执行尝试与状态事件保持追加记录。
查询至少返回节点输入版本、尝试历史、复用来源、输出产物、耗时、错误类别及关联日志。
初期保留取消操作为待设计能力，不把终止进程等同于完整的任务取消协议。
