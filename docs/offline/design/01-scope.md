# 目标与 PDF 范围

状态：设计或用例建议；具体批准范围见对应评审入口。

## 1. 目标与边界

- 每个阶段可由普通 Python 模块独立调用，并保存可检查的完整输入与输出。
- 重跑固定上游版本，不覆盖历史产物；不同方案可在隔离的语料和索引中比较。
- FastAPI 负责请求校验、任务提交和状态查询，worker 负责执行。
- Stage 定义输入输出和业务变换；ArtifactStore 管理快照；Runner 管理依赖、尝试与状态。
- 按 [TDD 流程](../01-tdd-plan.md) 分批设计和评审用例，用户确认后先写测试再实现；当前字段仍为设计建议。
- 首批建议单机共享文件保存产物；已确定 PostgreSQL 为状态库。
- 任务分发先评审状态库任务表与独立 worker；Redis、Kafka 的启用条件见 [技术选型说明](../03-technology-options.md)。
- 至少支持 10 用户同时操作和多 PDF 批次；内部文档/阶段并发独立配置，见 [并发与进度](../04-concurrency.md)。
- 当前对外处理范围为 PDF；Markdown 与 QA 对 CSV 是后续需求，仅预留扩展契约，不实现解析器或上传支持。
- 本轮不展开在线召回、生成、指标计算或评测集建设，也不选定生产模型。

### 1.1 已确认的首批 PDF 范围：方案 B

- 支持带文本层的 PDF，提取文本并保留页码、文本块与可追溯的原文位置。
- 提取嵌入的位图图片，保存图片字节、所在页、区域及来源关联。
- 图文关联首先基于页/区域定位，关联上下文的具体规则另行评审，不宣称已解决任意复杂版面的语义对应。
- parse 保存图片与来源，图片描述由独立 caption 阶段承担；本次选择不确定 caption 的业务规则。
- 表格中的可提取文字进入文本结果，首批不承诺还原表格行列或跨页表格结构。
- OCR、复杂多栏阅读顺序、矢量图识别和扫描件完整解析留待后续；需要这些能力的输入必须明确诊断。
- 已确认：不完整解析默认判失败并阻断下游，保留部分结果与诊断；首批 01～06 已全部通过，独立解析模块的 56 个测试通过。
- 已确认：疑似扫描正文保守判失败，诊断明确为风险判断；[扫描风险规则与默认阈值](../reviews/pdf-parse/03-scan-policy.md) 已评审通过。
- 已实现 PyMuPDF 统一提取文本/图片，保留页码与原始矩形坐标；[坐标约定](../reviews/pdf-parse/02-coordinates.md) 已通过，依赖版本由 uv.lock 固定，调用见 [使用说明](../05-pdf-parse-usage.md)。

首组行为用例见 [PDF parse 评审草案](../reviews/02-pdf-parse.md)；选择 B 不等于用例已通过或可以开始开发。
当前先完成 [parse 首批实施用例评审](../reviews/01-pdf-parse-cases.md) 与解析实现；chunk 既有草案暂缓。
已认可 20 页公开样本的质量；业务 PDF 由用户后续补充，当前不以业务一致性作为解析回归前提。
