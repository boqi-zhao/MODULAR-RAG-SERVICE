# 后续格式扩展边界

状态：设计或用例建议；具体批准范围见对应评审入口。

### 3.2 格式扩展边界

当前仅启用 PDF，后续至少支持 Markdown 文件及 QA 对形式的 CSV。
实现时将格式识别、解析器选择与 parse 执行分开；首批只注册 PDF 解析器，不编写空实现冒充支持。
接入元数据记录 source_format、原始文件名、声明的媒体类型与原始字节摘要；校验格式后再选择解析器。
未启用格式在接入校验时明确拒绝，不进入 PDF 流程，也不把 CSV 行数误计为上传文档数。
解析器的名称、版本、配置及格式专用参数进入 manifest 和执行指纹，保证重跑固定解析方案。
Stage、Runner、状态表和 API 的通用概念使用文档与批次，不以 PDF 页数作为所有文档的必需字段。

parse 输出统一的解析单元：单元键、类型、文本、层级/分组关系、元数据及带类型的来源定位。
通用字段与格式专用元数据分开，页码/版面区域只对适用的来源存在；输出 schema 必须带版本。
来源定位预留 PDF 页/区域、Markdown 源文本区间、CSV 记录序号与字段等类型，具体字段后续定义。
CSV 定位应指向解析后的记录与字段，不能把物理行号直接当作稳定记录身份。
解析文本偏移仍遵循第 3.1 节；映射回原始格式时使用对应定位类型，不强制转成 PDF 页码。
不同格式最终复用块身份、块表示、产物保存、编码和索引契约；专用规则放在格式适配器与分块策略中。

Markdown 后续需保留标题层级、列表/代码等结构及原文定位；图片能力由解析结果显式声明。
QA CSV 后续需保留 question/answer 的配对关系、记录定位和可选元数据，不能先拍平成无结构文本。
分块契约预留关联单元分组，后续可选择保持 QA 对完整；超长问答对的切分规则届时评审。
CSV 的列名映射、编码、缺失值、重复记录和错误处理策略，以及 Markdown 图片解析范围均留待后续设计。
这些格式不自动启用 caption/image_register；阶段计划根据配置与解析产物能力选择依赖。
一个上传文件仍是一份来源文档和一个批次文档项，其内部解析单元数量不改变批次 total。
后续若需把 CSV 每条 QA 当作独立文档，应单独设计导入模式及身份/进度规则，不隐式改变现有口径。
