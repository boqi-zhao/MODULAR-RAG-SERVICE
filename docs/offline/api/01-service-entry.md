# 第一步：启动服务与健康检查端点

状态：已实现；用户已通过 Postman 验证并确认提交。日期：2026-10-06。

## 本步目的

先让 FastAPI 服务能够启动，并让外部客户端通过 HTTP 得到响应。
端点就是客户端可以访问的接口地址；本步先做一个最简单的健康检查接口。

## 接口行为

| 项目 | 约定 |
| --- | --- |
| 请求 | `GET /health` |
| 输入 | 无需上传文件，也无需填写参数 |
| 正常响应 | HTTP 200，JSON 内容为 `{"status": "ok"}` |
| 含义 | 服务进程可以接收和响应请求 |

这个响应只证明接口能响应，不代表 PDF 已能解析、数据库已连接或任务能够完成。

请求的执行过程：客户端访问 `/health` → FastAPI 找到对应函数 → 函数返回状态 → FastAPI 转成 JSON 响应。

## 实现文件

- `src/api/__init__.py`：将接口目录定义为 Python 包。
- `src/api/main.py`：创建 FastAPI 应用，并定义健康检查端点；本步先放在一个文件里，便于理解。
- 根目录 `README.md`：补充启动命令与调用方法。
- 验证文件按实际需要补充；检查接口响应与应用能否启动。

启动命令：`uv run uvicorn api.main:app --app-dir src --host 127.0.0.1 --port 8080`。
调用命令：`curl http://127.0.0.1:8080/health`。
通过 `http://127.0.0.1:8080/docs` 查看 FastAPI 自动生成的接口页面。

## 验收与本步结束位置

1. 服务启动成功；调用 `/health` 得到约定的状态码与 JSON。
2. 接口页面中能看到 `/health`。
3. Ruff 检查与格式检查通过。
4. 展示实际代码与调用结果，说明应用入口、路由函数和返回值的关系，交给用户评审。

本步完成后停下；下一步再讨论 PDF 上传接口的输入、响应和文件保存规则。
本步不包含 PDF 解析、PostgreSQL、后台任务或 10 用户并发验收。

- `uv run ruff check .` 与 `uv run ruff format --check .` 均通过。
- 本步没有新增自动测试文件；上述验证为实际启动后的接口检查。
