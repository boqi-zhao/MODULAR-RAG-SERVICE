# 每个 Stage 的版本产物

**已确认要求**：每个可独立执行或调整策略的 Stage（阶段）都要落盘、可追溯、可复用。
**待评审方案**：下面的身份编码、manifest 字段和提交协议尚未冻结；当前解析仅有 [工作目录快照](02-pdf-parse.md)。

## 完成一个阶段意味着什么

Stage 负责业务变换，ArtifactStore 负责保存与校验，Runner 负责依赖和执行；不要求拆成三个微服务。
阶段输入输出先明确，结果包括结构化内容和图片等必需字节，新进程能独立读取。
下游指定**某个成功版本**，不能读“最新结果”或依赖上次调用的内存。被引用原文件和上游必须持续可读。

每份产物记录身份、契约、固定输入/摘要、策略/实现/依赖版本、完整有效配置、执行尝试及结果。
模型阶段另存实际模型、Prompt 和业务请求/响应，排除认证头与密钥。
先落盘并通过结构、引用、文件摘要校验，才能标记成功或供正常下游使用。
失败尝试保存实际输入、配置、部分结果及诊断，与成功产物分开；失败结果不能进入正常下游。
纯计算允许分步实现，但不能因此宣称 Stage 已完整交付。

## 身份和内容摘要分开

以下为原草案保留的建议，不把它们当成当前上传/解析 ID 实现。

| 身份 | 建议规则与含义 |
| --- | --- |
| document_id | 接入分配的逻辑文档身份；更新显式指定，不由路径/相同字节推断 |
| document_version_id | 文档 ID 与原始 SHA-256 的摘要；同一文档同字节可复用版本 |
| artifact_id | 每份候选产物新 ID，强制执行也不覆盖历史 |
| chunk_set_id / chunk_id | 集合用 chunk 产物 ID；块用集合 ID 与局部唯一键的摘要 |
| execution_id | 一次实际尝试，重试分配新 ID |
| run_id / batch_item_id | 一份批次计划 / 其中一个文档项；项绑定文档版本 |
| corpus_snapshot_id / index_snapshot_id | 固定语料清单 / 独立索引组合的身份 |

随机 ID 的编码在实现前冻结；路径只表示来源，SHA-256 用于核对内容，不充当所有业务身份。
相同字节可属于两个逻辑文档，可去重字节但不合并文档；文档移动不改变显式身份。
块身份不依赖增强后文字或路径，父子关系无环；下游编码/索引沿用块 ID。
当前上传编号与解析摘要型编号如何绑定，必须在正式产物设计时明确。

## 怎样判断可以复用

执行指纹用于寻找候选，包含 Stage/契约、实现与依赖、完整配置、固定输入引用和摘要；模型阶段含模型/Prompt。
影响输出的环境和随机种子要记录；运行时间、尝试 ID、日志不进入内容指纹。
结构化摘要使用有版本的规范化序列化：固定编码、键顺序、数值处理及默认值，先定义测试向量。
有序输入保持顺序，集合才排序；原始字节直接计算 SHA-256。

复用还要核对成功状态、契约兼容、完整输入/策略信息、所有必需文件摘要及用户/实验隔离范围。
相同原文件摘要不足以复用；丢失或损坏时明确拒绝，不偷偷换版本。
远程模型只有可变别名、无法固定版本时记录复现限制，原建议默认禁用自动复用。
指纹不保证 LLM 确定性，也不承诺并发同指纹只算一次；强制执行绕过复用生成新产物。

## 保存清单和目录：待评审

建议本机共享数据卷：成功结果 `artifacts/<artifact_id>/`，处理中 `staging/<execution_id>/`，失败记录 `attempts/`，原始字节 `blobs/`。
状态和引用放 PostgreSQL；不强制复制全部祖先，但迁移/备份必须包含全部被引用文件与产物。

manifest 是产物文件清单，建议 JSON；逐块可用 JSONL，图片/向量独立二进制文件。

| 字段组 | 建议记录 |
| --- | --- |
| 身份 | manifest/Stage 契约版本、artifact_id、execution_id、run_id、用户；文档项另含 batch_item_id |
| 输入 | 文档/语料版本、具名上游产物、文件/记录摘要及读取范围 |
| 实现 | 策略/代码版本与摘要、依赖锁及执行环境摘要 |
| 配置 | 完整有效配置与摘要、实际模型、Prompt 正文/版本、随机种子 |
| 输出 | 相对路径、类型、大小、SHA-256、记录数、输出 schema 版本 |
| 执行 | 开始/结束/耗时、结果、诊断、校验摘要和执行指纹 |
| 复现限制 | 可否复用、外部资源引用和版本、无法固定的信息 |

清单不能引用逃逸目录的路径。成功清单发布后不修改；失败清单与日志仅用于诊断。

## 提交和中断：待评审

1. PG 登记固定输入、计划、候选产物和尝试；worker 领取租约，在独立 staging 中执行。
2. 完成输出，核对模型、引用、完整清单及所有摘要，再写成功 manifest。
3. 短 PG 事务锁定所有权，复核租约与递增 fencing token（所有权代号），同文件系统原子发布目录。
4. 同一短事务登记已发布产物并标记 succeeded；事务内不做模型调用或大文件写入。

文件和 PG 没有共同事务：发布后未登记的产物需对账，核对原尝试和 token 才能补登记。
领取、续租、恢复、提交使用同一所有权协议；过期 worker 返回结果也不能覆盖接管后的执行。
失联先记 interrupted；过期尝试孤立目录仅诊断，不补登记成功。PG 成功但文件损坏则标不可用并阻断下游。
外部索引靠独立命名空间和提交标记；对象存储不能照搬 rename。初期不自动清理，后续回收先检查引用和活动任务。

## Stage 交付验收

- 保存后退出，新进程完整读回文字、图片和来源/策略信息。
- 指定固定上游复用，不重新上传或重算未受影响 Stage。
- 更换策略生成新版本，新旧结果共存，新下游绑定正确版本。
- 保存失败或产物丢失/损坏时拒绝成功/复用，失败尝试能排查。

换策略和失败恢复的操作区别见 [04 执行与调优](04-execution.md)；索引组合另见 [05](05-future-scope.md)。
