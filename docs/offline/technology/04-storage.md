# 本地文件与对象存储

状态：设计或用例建议；具体批准范围见对应评审入口。

## 6. 产物存储：单机文件与对象存储

实际问题：完整产物包括原文、图片、逐块输出和模型请求响应；应独立于任务进程保存并校验。
阶段计算可以跨进程，但各进程必须读取同一份固定产物，不能各自使用互不相通的本地目录。

**当前建议：首批按单机部署设计，使用共享本地目录；预留 ArtifactStore 边界。**
API、worker 和恢复进程在同一主机上访问相同数据卷；PostgreSQL 本身不会使文件自动共享。
文档记录数据卷位置、权限、备份与恢复步骤，并验证重启后仍可读取历史产物。
数据库保存产物 ID、校验摘要和存储定位，不以 worker 临时路径作为永久引用。
迁移到多机时再评审对象存储：使用唯一版本键、上传后校验、数据库提交引用和孤立对象回收。
对象存储不能照搬本地目录 rename 协议；存储迁移需要单独设计提交与恢复流程。
状态库和产物存储仍不共享事务，需要对账；采用 PostgreSQL 不能消除这类故障窗口。
两者备份需保留一致的引用闭包，恢复后执行完整性检查，不能只恢复数据库就宣布恢复成功。
向量后端在编码契约明确后评审；不根据组件数量决定选型，也不混淆存储便利与检索效果。
