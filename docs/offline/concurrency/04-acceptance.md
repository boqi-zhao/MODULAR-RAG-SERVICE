# 10 用户验收范围

状态：设计或用例建议；具体批准范围见对应评审入口。

## 6. 10 用户验收与后续 skill 脚本

测试脚本先独立可调用；未来 skill 负责组织参数、调用脚本和汇总报告，不承担服务内调度。
主验收使用至少 10 个不同用户身份并发操作，通过开始屏障产生重叠会话，每个用户有独立批次。
客户端持续观察进度并穿插查询/提交操作，直到所有批次到达终态，不能只测上传接口返回。
每批篇数可配置；100 是批次进度示例，不是默认强制每次测试上传 1000 篇。

| 场景 | 验证要求 |
| --- | --- |
| 10 用户正常流程 | 合法测试 PDF 在固定计划下全部成功，完整产物及启用的索引可用 |
| 内部并发为 1，再改为 3 | 两种配置下都支持 10 用户；有效并发不超额度，计数无漏项/重复 |
| 大小批次混合 | 大批次不无限阻塞其他用户，记录各用户首次执行与总等待时间 |
| 推送断开后重连 | 不重建批次、不重复计数，最新快照与状态查询一致 |
| PDF 损坏与模型失败 | 单独故障用例，明确失败和退避信息，不把失败当成功 |
| worker 崩溃与旧进程恢复 | 可以恢复，旧结果不能覆盖；失败恢复计数语义符合第 3 节 |
| 多用户隔离 | 状态、产物、索引和进度不能串到其他用户 |

报告记录：用户数、每批篇数、PDF hash/页数/大小/类型、硬件、配置、实现与模型版本。
测量提交延迟、进度更新延迟、总完成耗时及分位值、阶段排队/执行时间、资源峰值、连接池等待。
主验收不注入故障，要求无任务丢失、用户串数据、重复终态计数或非预期失败；故障测试另报。
客户端设定超时并保留服务最终状态；无限等待不算通过，时间阈值在基准负载确定后冻结。
先用可控阶段验证调度与进度，再用真实 PDF 和实际模型/索引完成端到端验收；前者不能替代后者。
数据库并发逻辑需在真实 PostgreSQL 上验证，不用 SQLite 测试结果推断 PostgreSQL 锁行为。
目前尚无业务实现，这些是后续验收契约，没有已达到 10 用户能力的实测结论。

## 7. 还需确定的测试边界

- 单 PDF 的大小/页数范围，是否覆盖扫描件、OCR、图片和长文档。
- 基准机器、模型接口配额、上传限制及典型批次规模。
- 用户认证方案、共享知识库需求，以及允许的进度延迟和完成时限。
- 文档级/语料级阶段的最终划分，及前台各处理阶段的文案。
