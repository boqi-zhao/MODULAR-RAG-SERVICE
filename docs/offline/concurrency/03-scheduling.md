# 内部额度与公平调度

状态：设计或用例建议；具体批准范围见对应评审入口。

## 5. 内部额度与公平调度

配置分别定义 max_active_documents、各阶段 max_executions、模型配额与单用户/单批次占用上限。
max_active_documents 按整个服务计算，不按进程分别计算；启动三个 worker 不能把上限乘三。
文档额度只在有可运行文档级节点时持有，跨阶段交接可保留；文档级链完成或进入退避/屏障等待时释放。
等待额度的节点保持 queued；先取得所需额度再领取，避免大量 running 任务实际只在等待槽位。
文档额度、阶段额度和执行租约关联，由 PostgreSQL 短事务协调；回收需检查所有者与 fencing token。
语料级执行只计入对应阶段额度，不持有等待其结果的全部文档额度，避免批次屏障导致槽位耗尽。
额度代表有效执行所有权；失联旧进程可能仍计算，接管时拒绝旧提交，并记录实际资源超额风险。
模型请求并发与每分钟调用量分别限制；CPU 解析与网络调用采用适合各自资源的执行方式。
耗时解析不阻塞 API 事件循环；上传采用流式或有界分片，避免整批文件同时读入内存。
按用户轮转调度，同一用户内部再按批次/文档排序，避免一个 100 篇批次长期占满槽位。
允许低负载时借用空闲额度；有其他用户排队时限制继续领取，初期不抢占已经运行的阶段。
公平性通过用户等待时间验证，`SKIP LOCKED` 只减少领取锁竞争，不替代公平调度策略。
API、worker、恢复进程有独立且有界的连接池；所有进程的池总量与 PostgreSQL 连接预算匹配。
SSE 连接数、用户数、worker 数和数据库连接数没有一一对应关系，不能直接全部设成 10。
上传/排队超出资源容量时明确报告限制；验收负载范围内不能靠拒绝其中用户满足 10 并发。
