# 扫描风险判定

状态：2026-10-06 用户评审通过；确认本文件的扫描风险规则、默认阈值、失败处理和首批整份 PDF 重跑方式。

## 为什么要检查

扫描 PDF 常把整页文字保存成图片：人能看到文字，但解析库可能取不到文字。
OCR 是把图片中的文字识别出来；首批不做 OCR，因此需要提示这类风险，避免把缺少正文的结果送到后续分块。
用户只需上传 PDF；以下参数由服务提供默认值，上传时无需填写。

## 每页检查什么

1. **提取到了多少文字**：统计字符数，忽略空格、换行等空白；中文、英文等使用同一计数规则。
2. **图片占页面多大比例**：按图片的矩形范围计算，只计算页面内的部分；多张图片重叠的区域只算一次。
   例如，图片合计覆盖页面面积的 80%，图片覆盖率就是 0.80；不按图片数量判断。

## 什么时候标记失败

同时满足以下两个条件时，记录“疑似需要 OCR”，整份 PDF 的解析结果标记为失败：

- 这一页的图片覆盖率至少为 80%（0.80）。
- 这一页提取到的非空白字符少于 80 个。

例如：覆盖率 80%、79 个字符会触发；覆盖率 79% 或字符数达到 80，则不触发这条规则。
普通短标题页、空白页不会仅因字数少触发；但满页照片且没有文字，也可能被这条规则误判。
因此提示写“疑似”，不声称已经确认图片里有扫描文字。

## 失败后怎么处理

- 记录出问题的页码、实际字符数、图片覆盖率和本次使用的阈值，方便排查。
- 某页有扫描风险或提取错误时，仍尽量解析其他页，保留实际取得的文字、图片和诊断。
- 只要有一页触发扫描风险或提取错误，这份文档就标记为解析失败。其他页面已经提取的内容仍保留，但本次结果暂不进入后续分块。
- 如果文件损坏等错误导致无法继续，则停止解析并说明原因。

按当前首批重跑方案，再次执行 parse 时会重新解析整份 PDF，暂不只重试失败的页面；保留上次的部分结果和诊断供比较。
重跑本身不能补出扫描图片里的文字；如果原文件和解析方法没有变化，扫描风险通常仍会触发。

服务配置也要先检查：字符数阈值必须是大于 0 的整数，覆盖率阈值必须大于 0 且不超过 1。
例如，覆盖率填成 1.2 属于配置错误，应在解析前拒绝，不算 PDF 本身解析失败。

## 这条规则有哪些局限

- 它通过图片面积和文字数量判断风险，不能保证发现所有漏字或缺失正文；只有小部分区域是扫描图片时，也可能漏判。
- 有些扫描 PDF 已经过 OCR，带有可提取文字，可能不触发规则；这不代表这些文字已核对正确。
- 提取出的文字有乱码时，先记录观察到的问题；首批暂不制定“乱码达到多少就失败”的规则。
- 测试应检查结果是否符合预期。扫描样本按规则返回失败，也算测试通过；不能为了让 20 页样本都解析成功而调整阈值。
