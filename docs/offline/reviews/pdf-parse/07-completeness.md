# 完整性判断的边界

状态：设计或用例建议；具体批准范围见对应评审入口。

## 完整性判断建议

完整性相对于方案 B 的承诺：检查应处理的页、文本与嵌入位图；不把尚未承诺的结构化表格恢复当成必需输出。
判失败使用已有执行状态 failed，并在诊断中区分打不开文件、处理异常、内容不完整和未支持能力。
“没有抛异常”不足以证明完整；同样，“某页没有文字”也不足以证明失败，可能是真实空白页。

| 检查类型 | 建议检查与结果 | 可验证边界 |
| --- | --- | --- |
| 逐页处理清单 | 原始 PDF 页数与每页处理记录对应；遗漏或处理异常判失败 | 可确认页是否处理，不保证页面文字毫无遗漏 |
| 图片提取与定位 | 枚举本范围内可见图片及出现位置，核对字节与来源关联；必需项失败判失败 | 出现位置与去重后的图片数量分开，不以二者数量相等验收 |
| 输出引用校验 | 文本区间、页码、图片定位与字节引用有效，输出文件可读取 | 可检测无效定位与丢失文件，不能证明语义正确 |
| 疑似扫描内容 | 按每页可提取文字数量与图片覆盖率判断 | 会有误判/漏判；规则与用例已评审通过，重写后仍需验证 |
| 文字质量异常 | 乱码、异常字符、疑似漏提取形成质量诊断 | 不能仅凭长度或字符比例断言全文完整 |

疑似需要 OCR 的候选包括大面积图片覆盖且文字很少的页，以及有可见内容但没有可提取文字的页。
页上只有页码或标题时仍可能有扫描正文；普通插图也可能占满页面，不能一律把图片当扫描文字。
必要时结合页面渲染辅助检查空白/可见内容，是否执行及资源成本在检测方案中另行确定。
参考：[PyMuPDF OCR 判定线索](https://pymupdf.readthedocs.io/en/latest/recipes-ocr.html)。
本项目建议先验证逐页清单、提取异常和引用完整性，再用明确标注的 PDF 样本评审质量检查。
诊断记录观察事实与使用的规则；“疑似需 OCR”与“已确认提取失败”分开，不虚构确定结论。
无法可靠自动发现的漏内容通过人工核对样本、回归测试及后续质量评估补充，不宣称自动检测覆盖所有 PDF。

### 首批判定政策与边界样本

疑似扫描的保守阻断、判断规则与默认阈值已确认，详见 [扫描风险判定](03-scan-policy.md)；原实现已删除，重写后重新验证，见 [实现状态](09-implementation-status.md)。

| 场景 | 建议处理 | 判断边界 |
| --- | --- | --- |
| 某页处理异常、必需图片丢失或定位失败 | failed，保存部分结果与诊断，阻断下游 | 已确认的明确失败行为 |
| 已核实空白页 | 正常通过该页，保留页序 | 无文字不能单独证明空白；无法核实时不能伪造空白结论 |
| 普通插图/图表，没有文本异常证据 | 图片按方案 B 保存，可正常通过 | 图片本身无可提取文字不等于整页需要 OCR |
| 图片覆盖率至少 80% 且非空白字符少于 80，疑似扫描正文 | 已确认保守判失败，诊断标为“疑似需 OCR” | 不声称已经确认扫描；接受一定误拒，重写后按边界用例核对 |
| 文字量少，但没有其他异常证据 | 正常处理，可记录观察信息 | 不把短标题、封面、目录或短页直接判失败 |
| 乱码迹象，无法确认内容丢失 | 先记录警告；明确达到严重质量规则时再判失败 | 严重规则、阈值及测试样本仍待定，不按语言简单判乱码 |

保守阻断使用已有失败状态，诊断区分确定失败与风险判定；误判通过修订检测规则与重跑处理。

对应边界样本需要人工明确预期，至少包含：

- 真空白页：不判失败，其他页正常处理，原始页序不变。
- 带标题/页码的扫描正文页：不能仅因提取到少量文字就通过。
- 满页普通插图：验证扫描检测的误拒风险，并据此评审规则，不预先保证能完全区分。
- 正常短文本页：不因文字少而失败。
- 不同语言、合法符号与真实乱码：避免把非中文字符误当乱码。

已确认的数字阈值将通过这些边界样本测试；解析库和定位粒度已确认，不重复选型。
